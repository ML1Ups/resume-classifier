# feature/experiment — эксперимент с ограничением нагрузки и без

Часть проекта [Resume Classifier](../../tree/main). Влита в `main` через [PR #29](../../pull/29),
релиз `v0.4.0`. Третья из трёх веток ДЗ 4.

## Что сделано

- **`scripts/experiment.py`** запускает источник и раз в ~4 с снимает показатели: глубину
  очереди (веб-API RabbitMQ — только для замеров, источник им не пользуется), память контейнеров
  (`docker stats`), число выполненных задач и время их выполнения (из PostgreSQL). На 90-й секунде
  добавляет второй воркер. Скорость источника берётся из его логов — это принятые брокером задачи.
- **`scripts/plot_experiment.py`** строит графики.
- Результаты двух прогонов по 3 минуты — в [`docs/experiment`](docs/experiment).

## Условия

27 366 резюме из `data/evaluation/full.csv`, `INFERENCE_SECONDS=0.5`, `WORKER_THREADS=4`, то есть
один воркер обрабатывает 8 задач/с.

| Режим | Лимит очереди | prefetch |
|---|---:|---:|
| с ограничениями | 100 | 4 |
| без ограничений | нет | нет (quorum-очередь сама ограничивает 2000 на потребителя) |

## Результаты

![Эксперимент](docs/experiment/experiment.png)

| Показатель | С ограничениями: 1 → 2 воркера | Без ограничений: 1 → 2 воркера |
|---|---|---|
| Глубина очереди (ready) | 77–101, не выше лимита | до 25 200 — весь файл |
| В обработке у воркеров (unacked) | 4 → 8 | 2000 → 4000 |
| Скорость источника | ≈ 7,5–8 → ≈ 15–16 задач/с | ≈ 1650 задач/с, файл выгружен за 17 с |
| Пропускная способность | 8 → 16 задач/с | 8 → 16 задач/с |
| Время выполнения задачи | ≈ 12,5 → ≈ 6,3 с, стабильно | растёт без предела: 175 с к концу |
| Память RabbitMQ | ≈ 100 МБ | ≈ 165 МБ и растёт с размером очереди |
| Память источника | 45 МБ, не меняется | 45 МБ до конца файла |

## Выводы

- **Очередь не превышает лимит.** Quorum-очередь допускает перелёт на одно сообщение (101 при
  лимите 100), дальше брокер отклоняет публикации.
- **Скорость источника сама совпадает с пропускной способностью воркеров:** 8 задач/с с одним
  воркером, 15–16 — с двумя. Второй воркер подключён командой `docker compose up -d --scale
  worker=2` без изменения кода, и источник ускорился сам.
- **Время задачи ограничено:** ≈ (лимит + prefetch) / пропускная способность = 104 / 8 ≈ 13 с с
  одним воркером и ≈ 6,5 с с двумя.
- **Без ограничений** быстрый источник за секунды перекладывает всю работу в брокер: очередь и
  память брокера растут вместе с файлом, а каждая следующая задача ждёт всё дольше. Второй воркер
  удваивает пропускную способность, но очередь в 21 тысячу задач он разберёт только за ~22 минуты.
- **prefetch тоже важен:** без лимита каждый воркер забирает себе 2000 сообщений, которых больше
  никто не может взять, а при его падении они все возвращаются в очередь со счётчиком неудачных
  доставок +1.

## Как повторить

Нужен собранный `data/evaluation/full.csv` (см. [`data/README.md`](data/README.md)) и поднятый
стек:

```bash
set -a && . ./.env && set +a
export COMPOSE_PROJECT_NAME=resume-classifier RABBITMQ_UI_PORT=15672
uv run python scripts/experiment.py limited
uv run python scripts/experiment.py unlimited
uv run python scripts/plot_experiment.py
```

Пароли и порты скрипт берёт из окружения, поэтому сначала загружается `.env`. Очередь он сам
пересоздаёт под нужный режим.
