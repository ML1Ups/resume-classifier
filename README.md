# feature/ml-training — эксперименты и реестр моделей

Часть проекта [Resume Classifier](../../tree/main). Влита в `main` через [PR #19](../../pull/19).
Третья из четырёх веток с MLflow.

## Что сделано

- `ml/train.py` — один запуск обучения: EDA, четыре модели, выбор лучшей, регистрация в реестре;
- `ml/artifacts.py` — метрики, графики EDA и разбор ошибок модели;
- `ml/registry.py` — показывает версии модели и переносит alias;
- в группу `ml` добавлены mlflow и matplotlib;
- Dockerfile получил аргумент `UV_GROUPS`: из одного файла собираются образ приложения (группа
  `web`) и образ обучения (`web` и `ml`);
- сервис `train` в `docker-compose.yml`: ждёт готовности MLflow, обучает модели и завершается.
  Приложение стартует только после его успешного завершения;
- 4 новых теста, всего 38. Smoke-тест проверяет, что в реестре появился alias `champion`.

## Что записывается в MLflow

Эксперимент `resume-classifier-hw3`, пять запусков:

| Запуск | Модель |
|---|---|
| `eda` | — |
| `baseline_dummy` | самый частый класс |
| `logreg_words` | TF-IDF по словам, логистическая регрессия |
| `svm_bigrams` | TF-IDF по словам и парам слов, линейный SVM |
| `logreg_characters` | TF-IDF по символьным 3–5-граммам, логистическая регрессия |

**EDA.** Строится только по train, чтобы не подсматривать в проверочные части: распределение
классов и длина резюме по классам (графики), частые слова, сводка в JSON и выводы в
`findings.md`. Сюда же записан отчёт о подготовке данных.

**Датасеты.** Все четыре части (full, train, validation, test) зарегистрированы через
`mlflow.data`: у каждой свой digest и источник. Запуск ссылается на те части, которые
использовал, с контекстом `training`, `validation` или `testing`. В каждом запуске лежит
`data/lineage.json` — как части получены из исходного файла, а в тегах — SHA-256 файла.

**Параметры и метрики.** Параметры векторизатора и классификатора, размеры частей, seed.
Метрики на validation: accuracy, balanced accuracy, macro-F1, weighted-F1 и время обучения.

**Диагностика.** Отчёт по классам, матрица ошибок (картинка и CSV), все предсказания, отдельно
ошибки и самые частые пары перепутанных классов.

**Модель.** Каждая модель сохранена вместе с сигнатурой и примером входа.

## Выбор лучшей модели

- основная метрика — macro-F1 на validation: классы несбалансированы, а она даёт каждому классу
  одинаковый вес;
- при равенстве побеждает более простая модель;
- test используется один раз — для уже выбранной модели;
- три модели регистрируются в реестре как версии `resume-classifier`, baseline в реестр не
  попадает: он нужен только для сравнения;
- лучшая версия получает alias `champion`. Сравнение всех моделей лежит в её запуске:
  `comparison/comparison.csv`.

На настоящем датасете (27 366 резюме, 34 сферы) лучшей стала `logreg_characters`: macro-F1 0,365
на validation и 0,365 на test. На учебном наборе все три модели набирают 1,0, и по правилу простоты
`champion` достаётся `logreg_words`.

## Как проверить

Настоящий датасет в git не хранится, поэтому проще запустить на учебном:

```bash
cp .env.example .env
TRAIN_DATA_PATH=/input/resumes_demo.csv docker compose up -d --build
docker compose logs train
docker compose run --rm train python -m resume_classifier.ml.registry
```

Последняя команда печатает версии модели и то, на какую из них указывает `champion`.
Интерфейс MLflow — http://127.0.0.1:5050.

Чтобы обучить на настоящих данных, нужно положить файл в `data/cv_target.csv` (откуда взять —
в [`data/README.md`](data/README.md)) и запустить `docker compose up -d --build` без переменной
`TRAIN_DATA_PATH`.

Модель из реестра начинает отвечать на запросы в следующей ветке,
[`feature/process`](../../tree/feature/process).
