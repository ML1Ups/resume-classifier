# feature/ml-data — данные и их подготовка

Часть проекта [Resume Classifier](../../tree/main). Влита в `main` через [PR #17](../../pull/17).
Первая из четырёх веток с MLflow.

## Что сделано

- группа зависимостей `ml` в `pyproject.toml`: pandas и scikit-learn. В образ приложения она не
  попадает: Dockerfile ставит только группу `web`;
- `ml/prepare.py` — превращает выгрузку резюме в таблицу «текст — профессиональная сфера»;
- `ml/dataset.py` — читает CSV, считает SHA-256 файла, делит данные на train / validation / test
  и собирает описание их происхождения (lineage);
- учебный набор `data/resumes_demo.csv` и скрипт `scripts/generate_demo_data.py`, который его
  создаёт;
- [`data/README.md`](data/README.md) — откуда взять настоящий датасет и что с ним делается;
- 18 новых тестов, всего 34.

## Два набора данных

| Набор | Строк | Классов | Где лежит | Зачем |
|---|---:|---:|---|---|
| `cv_target.csv` | 28 935 | 34 после очистки | вне git: в нём персональные данные | обучение настоящей модели |
| `resumes_demo.csv` | 240 | 6 | в git | тесты, smoke-тест и CI |

Формат определяется по колонкам: если есть `professionList`, файл считается выгрузкой резюме и
проходит подготовку; иначе нужны готовые колонки `text` и `category`.

## Подготовка выгрузки

- **Цель** — сфера из `professionList[*].codeProfessionalSphere`. Остаются резюме, у которых
  сфера ровно одна.
- **Текст** собирается из желаемой должности, навыков, должностей, обязанностей и достижений на
  прошлых работах, квалификации, специальности и уровня образования. HTML-теги вырезаются, длина
  ограничена 20 000 символов.
- **Не признаки**: идентификаторы, возраст, пол, названия компаний и вузов. Вместо исходного `id`
  дальше идёт его хеш `record_id`.
- **Повторы**: одинаковый текст с той же сферой остаётся один раз.
- **Редкие сферы**: меньше 10 резюме или 10 независимых групп — убираются, иначе их не хватит на
  три части.

Из 28 935 резюме остаётся 27 366. Сколько строк ушло на каждом шаге — в
[`data/README.md`](data/README.md).

## Разбиение

| Часть | Настоящий датасет | Учебный набор |
|---|---:|---:|
| train | 16 332 | 144 |
| validation | 5 579 | 48 |
| test | 5 455 | 48 |

Доли около 60/20/20, seed 42, в каждой части есть все классы.

**Почему по группам.** У одного соискателя бывает несколько резюме, а одинаковый текст встречается
у разных людей. Если такие резюме попадут и в обучение, и в проверку, метрика окажется завышенной.
Поэтому резюме с общим `candidateId` или одинаковым текстом объединяются в группу, и группа целиком
уходит в одну часть (`StratifiedGroupKFold`). Учебный набор делится обычным стратифицированным
разбиением: групп в нём нет.

**Что такое lineage.** Словарь с источником файла, его SHA-256, стратегией и seed разбиения,
а для каждой части — числом строк, digest и списком `record_id`. В следующих ветках он записывается в
MLflow рядом с каждым запуском.

## Как проверить

```bash
cp .env.example .env
uv sync
./scripts/test.sh
uv run python scripts/generate_demo_data.py
git status --short data
```

Последние две команды пересоздают учебный набор: генератор детерминированный, поэтому
`git status` ничего не выводит.

Трекинг-сервер появляется в следующей ветке,
[`feature/mlflow-server`](../../tree/feature/mlflow-server).
