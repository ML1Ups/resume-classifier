# Данные

В git лежит только учебный набор `resumes_demo.csv`. Настоящий датасет содержит персональные
данные и в репозитории не хранится.

## Настоящий датасет: `cv_target.csv`

28 935 резюме портала «Работа России» по Санкт-Петербургу, 48 колонок.

- Откуда взять: [cloud.mail.ru/public/mS3v/9ky1yTFYh](https://cloud.mail.ru/public/mS3v/9ky1yTFYh),
  архив `cv_target.csv.zip`. Распаковать в `data/cv_target.csv`.
- Первоисточник: открытые данные Роструда, набор
  [7710538364-cv](https://opendata.trudvsem.ru/7710538364-cv/).
- По умолчанию обучение в `docker compose` берёт именно этот файл (`TRAIN_DATA_PATH`).

### Цель и признаки

Цель — профессиональная сфера из `professionList[*].codeProfessionalSphere`.

Текст для модели собирается из желаемой должности, навыков, должностей, обязанностей и
достижений на прошлых работах, квалификации, специальности и уровня образования. Идентификаторы,
возраст, пол, названия компаний и вузов в признаки не входят.

### Очистка

| Что убрано | Строк |
|---|---:|
| резюме без сферы | 1 |
| повторы одинакового текста с той же сферой | 1 558 |
| сферы `Logistic` (9) и `Entertainment` (1): слишком мало примеров | 10 |

Остаётся 27 366 резюме в 34 сферах.

### Разбиение

Train / validation / test: 16 332 / 5 579 / 5 455 (около 60/20/20), `StratifiedGroupKFold`,
seed 42. В одну группу попадают все резюме одного `candidateId` и все одинаковые тексты, поэтому
один человек или один текст не оказывается сразу в обучении и в проверке.

## Учебный набор: `resumes_demo.csv`

240 синтетических резюме в 6 категориях, колонки `text` и `category`. Сгенерирован скриптом
`scripts/generate_demo_data.py`. Нужен для тестов, smoke-теста и CI, где настоящего датасета нет:

```bash
TRAIN_DATA_PATH=/input/resumes_demo.csv docker compose up -d --build
```


### Версии для демонстрации API

Из одного `cv_target.csv` создаются две воспроизводимые версии:

```bash
uv run python scripts/build_evaluation_datasets.py
```

В `data/evaluation/` появляются:

- `v1_train.csv`, `v1_validation.csv`, `test_v1.csv`;
- `v2_train.csv`, `v2_validation.csv`, `test_v2.csv`;
- `full.csv`;
- `manifest.json`.

`v1` использует весь train split, а `v2` — стратифицированные 10% от того же train split.
Validation и test между версиями совпадают. Поэтому сравнение `demo-v1` и `demo-v2` показывает
влияние объёма обучающих данных, а не изменение тестовой выборки.
